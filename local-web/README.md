# MoonBridge Activity — local web demonstration

This is a MoonBridge-branded, **localhost-only** web app for presenting the Windows activity workflow with synthetic workers. It implements the desktop app's pairing, context, upload, and signout API against a local SQLite database. The browser provides clock and break controls, code approval, connection controls, and an activity report.

All data in this app is synthetic or generated by the local desktop app. The server binds to `127.0.0.1` and does not connect to MoonBridge production.

## Start

Requires Node.js 24 or newer. No package installation is needed for normal use.

```powershell
cd C:\Users\william.MB\Desktop\projects\TimeTrackerApp\local-web
npm.cmd start
```

Open **http://127.0.0.1:4317/** in a browser. Leave that terminal running. The SQLite file is created at `data/moonbridge-local.sqlite`; **Reset demo data** in the web footer clears synthetic shifts, pairings, and intervals. Stop the server with Ctrl+C.

Run the integration tests with `npm.cmd test`.

## Connect the Windows app

Use the MoonBridge Activity Windows installer in `../desktop/src-tauri/target/release/bundle/nsis/`, or run the release executable in `../desktop/src-tauri/target/release/`. On first launch, set its MoonBridge server address to **`http://127.0.0.1:4317`**. The desktop allows HTTP for localhost. If it is already paired to another server, choose **Change worker** before changing the address.

The **Open MoonBridge Activity** link in the browser works after the installer registers the `moonbridge://open` protocol. When running the executable without installation, open it manually.

## What the local server implements

The desktop uses `POST /api/desktop/pair/start`, `POST /api/desktop/pair/complete`, `GET /api/desktop/context`, `POST /api/desktop/activity/batch`, and `POST /api/desktop/signout`. The browser approves codes through `POST /api/desktop/pair/approve`. Pairing codes expire after five minutes. The server binds tokens to a worker, open shift, and device, accepts event-ID retries once, revokes old pairings on handoff, and marks uncovered report time as **unverified**.

This is a presentation environment with selectable synthetic worker sessions. It does not implement MoonBridge's production SSO, tenant/site permissions, payroll rules, or deployment configuration. Its report does not change paid hours. A production integration still needs the remote MoonBridge web app and backend work described in `../WEB-APP-INTEGRATION-BUILD-INSTRUCTIONS.md`.
